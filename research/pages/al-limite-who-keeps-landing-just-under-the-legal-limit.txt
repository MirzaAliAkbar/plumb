 Al límite — who keeps landing just under the legal limit?
 Search any Spanish public body and see how many of its no-tender contracts stop just short of €15,000 — with the uncertainty, and no accusations.

 In one minute
 What it is : a free website where anyone can look up a Spanish public body and see whether its no-tender "minor contracts" pile up just under the €15,000 legal limit, with a 95% confidence interval and a plain-language explanation.
 Who it is for : residents, local reporters, opposition councillors and auditors, who cannot go through 1.47 million contract records themselves.
 What it found : nationwide, 68,251 contracts sit in the last €1,000 before the limit where 19,009 would be expected, 3.6 times as many. 893 pages carry a signal.
 Where the AI is : a small open model (Qwen3-4B, on a laptop) chooses the facts and writes the caveats and what to check. The code writes every figure, and a verifier rejected 1,208 drafts.
 Try it in one click : a body with a signal · a body with no signal · the national picture 
 Inspiration
 In Spain a public body can hand out a "minor contract" directly, with no tender, as long as it costs less than
€15,000 (€40,000 for building works). Splitting a job into pieces to stay under that line is illegal, but hard to
see: each contract looks fine on its own. What gives it away is the shape of the whole pile. If the limit did not
matter, there would be about as many €14,500 contracts as €13,500 ones.
 I had tested this idea by hand on one province. The data to do it for the whole country is public, but it comes as
thousands of XML files that no neighbour, local reporter or opposition councillor is going to open. Spain's own
procurement supervisor has written that it lacks aggregated data on minor contracts. So I built the tool I wanted
to exist.
 What it does
 Search 7,663 contracting bodies and 963 entities: town councils, ministries, universities, public companies.
 Shows "the wall" : the body's contract amounts as a histogram, with the legal limit, the €1,000 band right
under it, and the reference band used to work out how many contracts you would expect there.
 Observed vs expected, with honesty about uncertainty : an exact 95% confidence interval, a four-level label
(signal / weak hint / no signal / sample too small) and a warning when the sample is thin.
 Lists the actual contracts just under the limit, each linked to its official publication; shows repeat
awardees under a letter, not a name; and compares the monthly pattern to rule out a simple year-end rush.
 Explains each flagged case in plain language , in Spanish and English: what the data shows, what it cannot
show, what you could check. Written with a small open AI model and verified by code.
 Ranks bodies by the cautious end of the interval, so a body with four contracts cannot top the list.
 Nationwide, 2023–2025: 68,251 services and supplies contracts sit in the last €1,000 before the limit where
19,009 would be expected — 3.6 times as many (95% CI 3.56–3.63). For works it is 4.25 times (4.15–4.35).
684 bodies show a statistically solid signal for services and supplies.
 Who it is for
 A resident or a local reporter types the name of their town council and sees, in ten seconds, whether its contracts bunch under the limit and how sure the data can be.
 What they can do next : each flagged page lists the actual contracts, linked to the official record, and a short "what can be checked" list. The next step is a concrete information request, not an accusation.
 What it costs them : nothing. No account, no tracking, works on a phone, in Spanish or English.
 Honest status : nobody outside the project has used it yet, and no audit institution has reviewed the list. That is the next step.
 How I built it
 Data : the national procurement platform's open dataset of minor contracts (ATOM feeds with CODICE XML),
2023–2026: 2.06 million entries, 1.99 million distinct contracts after keeping the latest version of each and
dropping cancelled ones; 1.47 million analysed. A streaming parser loads them into SQLite.
 Statistics (Python, numpy/scipy): counts in the band under the limit vs a five-times-wider reference band.
Treating counts as Poisson, the near count is binomial given the window total, which gives an exact
Clopper-Pearson interval for the ratio and a one-sided test. Thousands of bodies are tested at once, so
p-values are corrected with Benjamini-Hochberg. A body is flagged only with ≥30 contracts in the window, ≥10
near the limit, q < 0.01 and a lower bound ≥ 2.
 Checks : a "fake limit" sweep from €7,000 to €18,000 (the pile-up appears only at the legal limit, not at
round numbers like €10,000), stability by year and by month, and 52 automated tests, including simulated
coverage of the interval and the false-positive rate.
 Web : a static site, vanilla JavaScript, hand-written SVG charts, no dependencies and no backend. Spanish
with an English toggle, keyboard-navigable, dark mode, data tables behind every chart, works on a phone.
 One command ( python -m allimite todo ) rebuilds everything from the download.
 AI implementation — and how it is kept honest
 No AI computes a number. A language model does one thing: turn each flagged body's statistics into an explanation
a non-statistician can read, in two languages.
 Open and local : Qwen3-4B (Apache 2.0) running through llama.cpp on my laptop's integrated GPU. No paid API,
no account, nothing leaves the machine. Explanations are precomputed, so the public site runs no model.
 The model never rewrites a figure. The code writes every fact as an exact sentence. The model reads them,
chooses which facts matter most for that body, and writes in its own words the caveats and the concrete things
to check. Its output is forced into a JSON schema by grammar-constrained decoding.
 A verifier reads every text : each sentence with digits must match a fact (same numbers, near-identical
wording); the three core facts must be there; no digits in the model's own sections; citations must point to
real contracts; no accusatory vocabulary; the caveat must be present. Three failed drafts → a fixed template,
labelled as such. Everything is re-verified when the site is built.
 No names : the model never sees an awardee's name, so it cannot repeat one.
 Result: 893 of 893 flagged pages carry an explanation in Spanish and English (1,620 of the 1,786 texts were written by the model and passed the verifier; the rest come from a checked template); the verifier rejected 1,208 drafts on the way.
 A representative input and output
 One flagged body, copied from resultados/explicaciones.json in the repository (record 10000120000808 ).
 Input to the model — a numbered list of fact sentences written by the code, with no names. Among them:
 Between 2023 and 2025, this body awarded 68 minor contracts for services and supplies above 14,000 and up to 15,000 euros, just under the legal limit. If those amounts were spread as in the band immediately below, 11.4 contracts would be expected. The observed-to-expected ratio is 6.0, with a 95% confidence interval of 4.1 to 8.6. December accounts for 1% of the contracts just under the limit, compared with 4% of all its services and supplies contracts. The contracts just under the limit are spread across 49 different awardees. Contract [1], for 14,817.32 euros, was awarded in October 2025.
 Output, first draft — rejected by the verifier (reason logged: figures in the model's own section; it wrote a year):
 {"hechos_elegidos": [4, 6, 7],
 "no_demuestran": "The data shows that some contracts are just under the limit, but it doesn't prove any wrongdoing. Prices may be low, budgets fixed, or needs separate. Statistical patterns don't indicate improper actions.",
 "revisar": "Check the contracts for 2025 to see if they repeat or match needs. Review awardee A's contracts to see if they are for similar services. Look at December's contracts to see if they are unusually low in value."}
 Output, accepted draft — the two sections the model wrote, as published under the data paragraph:
 What it cannot show: The data shows that some contracts are just under the legal limit, but it doesn't prove any violations. Prices could be lower than expected due to market conditions or budget constraints. The statistical pattern doesn't indicate improper actions by the body or its agents.
 What can be checked: Check the details of contract [1] to see what was purchased and the reason for the amount. Verify if multiple contracts relate to the same service or need. Review the distribution of contracts across different awardees to ensure no single provider is overused.
 For this body the verifier rejected 3 drafts (1 in Spanish, 2 in English) before both languages passed.
 What was tested, what failed and what changed
 First design, dropped after testing. The model wrote the data paragraph and a checker confirmed that every number in it was a computed one. Reading the outputs showed texts that passed and were still wrong: a ratio of 34.2 written as "34.2% of contracts", or the wrong price band. I changed the design so the model never restates a figure.
 What the verifier caught in the final run. It rejected 1,208 drafts (833 in English, 375 in Spanish): 1,077 put figures in the model's own sections, 99 lacked the caveat, 55 cited a contract that does not exist, 36 used accusatory wording or spoke of contract splitting outside the caveat, and 11 were too long. A draft can fail for more than one reason. 314 of the 893 flagged pages passed first time in both languages.
 Where the model still fails. After three failed drafts the page gets a fixed template, labelled as such: 166 of the 1,786 texts (37 in Spanish, 129 in English). The 4B model is clearly weaker in English.
 Statistics. Automated tests include simulations of the interval's coverage and of the false-positive rate. An independent recount in plain SQL must match the published figures, and it does.
 Website. Checked in a headless browser in Spanish and English, at desktop width and at 390 px: no console errors, no horizontal scrolling. That review led to round axis steps, the town council ranked above the provincial body when you search a town's name, and one-click examples on the home page for visitors who do not know Spanish body names.
 Limits. The verifier checks figures, structure and tone, not whether each suggestion is the most useful one. Only bodies on the national platform are covered. The indicator cannot tell whether any contract was actually split.
 Challenges I ran into
 A small model can copy every number correctly and still say something false. My first design let the model
write the data paragraph, with a checker that every number in the text was one of the computed ones. It passed
texts like "34.2% of the contracts…" when 34.2 was a ratio, or described the wrong price band. Matching numbers
is not matching meaning. I redesigned it so the model selects and explains but never restates figures.
 Messy public data : the same contract appears many times as it is updated; some are cancelled later; dates in
the year 0202; VAT-inclusive amounts typed into the VAT-exclusive field; half the contracts have no product code.
 Not overclaiming : with thousands of bodies, some will look extreme by chance. Hence exact intervals, minimum
sample sizes, a multiple-comparison correction, and ranking by the lower bound rather than the headline ratio.
 Naming : these are real institutions. I decided the site would name public bodies (they are accountable) but
never people or companies, and would say on every page what the indicator cannot prove.
 Accomplishments I am proud of
 A national picture that, as far as I know, was not available to the public in this form.
 A use of AI where the failure mode I found is documented, and the fix is structural rather than a disclaimer.
 Every number on the site can be regenerated by one command and traced to a file with its SHA-256.
 What I learned
 That the responsible way to use a language model on numbers is to keep the numbers out of its hands; that a
confidence interval is a better headline than a point estimate; and how much of a data project is deciding what
you will not say.
 What's next
 Add the regional platforms (Catalonia, Basque Country, Madrid, Andalusia, Galicia…), which publish separately.
 Use the model, with the same kind of verification, to summarise what the contracts near the limit are for.
 Track each body over time and after elections; alert when a body's pattern changes.
 Share the list with audit institutions and local journalists, and add a way for public bodies to reply.
 Tools, libraries and AI tools used
 Data : Plataforma de Contratación del Sector Público (Ministerio de Hacienda), open dataset of minor contracts, yearly files 2023–2026, downloaded on 15 November 2026. Reused with the source cited; the project is not affiliated with or endorsed by the Ministry.
 Libraries : Python with numpy, pandas, scipy, lxml and requests; SQLite. The website has no JavaScript dependencies and no build step; the charts are hand-written SVG. No template or starter kit was used.
 Model and runtime : Qwen3-4B (Apache 2.0, Alibaba Cloud) run locally through llama.cpp (MIT). No hosted model API.
 AI assistance : the code was written with the help of an AI coding assistant (Claude, Anthropic). Every figure on the site is computed by the code and re-checked by an independent recount.
 Demo video : narrated with a synthetic voice (Kokoro-82M, an open-weights text-to-speech model run locally); the script and the screen recordings are of the real site.
 Licence : the code is MIT.
 How and when it was built
 Team: one person. I did the data pipeline, the statistics, the verifier, the website and the video.
 Built from scratch on 15–16 November 2026 (first commit 15 Nov 2026), inside the submission period of every event it is entered in: SLAY HACKS, Code for Change, LaunchPad Hacks, AI OpenBuild, Silicon Valley Buildathon and GenHacks. It is one project with one page, entered in each of those hackathons. Code: https://github.com/antonmareo10/al-limite (MIT).
 The question comes from my earlier data-journalism pieces on minor contracts in one Spanish province (Bizkaia); no code from them was reused. This is a new national analysis with intervals, a placebo check and verified AI explanations.
 I wrote it with the help of an AI coding assistant (Claude, Anthropic). Every figure is computed by the code and re-checked by an independent recount.
 Try it
 Live site: https://al-limite-two.vercel.app (opens in English or Spanish to match your browser; toggle top right)
 Code and full method: https://github.com/antonmareo10/al-limite 
 Run it yourself
 The live demo needs nothing: open https://al-limite-two.vercel.app and search a town or a ministry. To run it locally (the repository already contains the precomputed data the site needs):
 pip install -r requirements.txt
python -m allimite servir # http://127.0.0.1:8000
 To rebuild everything from the public data and run the checks:
 python -m allimite todo # download (1.1 GB) → SQLite → analysis → explanations → site data
python -m pytest # 52 tests
python -m allimite.check # recounts the national figures with independent SQL and compares
 Regenerating the AI explanations also needs a local llama.cpp server with the Qwen3-4B model; the README has the command. No credentials or accounts are needed at any step.
